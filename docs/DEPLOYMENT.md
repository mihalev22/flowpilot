# Deployment Guide (Ubuntu VPS)

Step-by-step instructions for deploying FlowPilot on a clean Ubuntu VPS
with Docker Compose.

> Status: **documentation only — not deployed yet.** The commands below
> were rehearsed locally (HTTPS path verified with a self-signed
> certificate and a `docker-compose.override.yml`), but the real VPS
> deployment has not been performed. See [SECURITY.md](./SECURITY.md)
> for the security posture and known limitations.

## Target Architecture

```
Internet
   ↓
HTTPS :443
   ↓
Nginx (docker, only published ports: 80, 443)
   ├── /            → frontend static files (frontend_dist volume)
   └── /api/*       → backend:8000 (internal network)
                        ↓
                     PostgreSQL (compose network, no published ports)
```

Properties of this setup:

- PostgreSQL is never reachable from the Internet (no published ports,
  internal compose network only).
- The backend is not published either: it is only reachable through
  nginx (`expose: 8000` inside the compose network).
- nginx is the single entry point.
- The frontend is built in its own multi-stage image; an init container
  copies `dist/` into the shared `frontend_dist` volume.
- The backend runs `alembic upgrade head` on every start
  (`backend/entrypoint.sh`), then loads demo data **only** when
  `AI_MODE=mock` and the database is empty, then starts uvicorn.

## Requirements

Mandatory:

- Ubuntu LTS server (20.04 / 22.04 / 24.04) with SSH access and sudo.
- Docker Engine + Docker Compose plugin (v2, `docker compose ...`).
- Git.
- Open inbound ports 80 and 443 (TCP).
- For HTTPS: a domain name with a DNS **A record** pointing to the
  server IP. Without a domain the stack works over plain HTTP on the
  server IP.

Recommended (not required): 1 vCPU / 1 GB RAM is enough for demo
workloads of this project; PostgreSQL + backend + nginx together use
well under 500 MB.

## 1. Server Initialization

```bash
ssh root@YOUR_SERVER_IP

apt update && apt upgrade -y

curl -fsSL https://get.docker.com | sh
docker --version
docker compose version

apt install -y git

mkdir -p /opt/flowpilot
cd /opt/flowpilot
git clone https://github.com/<your-username>/flowpilot.git .
```

## 2. Firewall (UFW)

Allow SSH **before** enabling the firewall, otherwise you will lock
yourself out:

```bash
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
ufw status verbose
```

PostgreSQL (5432) must NOT be opened: it lives inside the compose
network and has no published ports. Do not run
`ufw allow 5432`.

## 3. Production `.env`

Create `/opt/flowpilot/.env` (next to `docker-compose.yml`). It is
gitignored, never committed, and read by compose at runtime:

```bash
cd /opt/flowpilot
cp .env.example .env
chmod 600 .env
nano .env
```

Variables by category (placeholders only — never put real secrets in
git, README, or screenshots):

```env
# --- JWT auth ---
JWT_SECRET=<generate: openssl rand -base64 48>
JWT_EXPIRE_MINUTES=60

# --- Database (compose builds DATABASE_URL from these) ---
POSTGRES_USER=flowpilot
POSTGRES_PASSWORD=<generate: openssl rand -base64 24>
POSTGRES_DB=flowpilot

# --- AI ---
AI_MODE=mock              # mock | live
AI_PROVIDER=mock          # mock | openai | qwen
AI_API_KEY=<provider-key> # only required when provider is openai/qwen

# --- Telegram ---
TELEGRAM_BOT_TOKEN=<token from @BotFather>
TELEGRAM_WEBHOOK_SECRET=<generate: openssl rand -hex 24>

# --- CORS (same-origin behind nginx, kept for local dev) ---
CORS_ORIGINS=https://your-domain.example
```

Notes:

- `DATABASE_URL` is generated by compose
  (`postgresql+psycopg2://$POSTGRES_USER:$POSTGRES_PASSWORD@postgres:5432/$POSTGRES_DB`) —
  do not set it manually in production.
- `AI_MODE=mock` makes the backend seed public demo credentials
  (`admin@luna.ru / admin12345`) on an empty database. For a public
  server prefer `AI_MODE=live` (or register your own account and
  treat the demo one accordingly): the first account registered via
  `/register` becomes the business admin.

## 4. Deploy (HTTP first)

```bash
cd /opt/flowpilot
docker compose up --build -d

docker compose ps
curl http://localhost/api/health     # {"status":"ok"}
```

What happens automatically on first start:

1. PostgreSQL starts (health-checked).
2. Backend waits for the healthy DB, runs `alembic upgrade head`, then
   (only `AI_MODE=mock`, empty DB) seeds demo data, then starts uvicorn.
3. The frontend init container copies the built `dist/` into the
   `frontend_dist` volume and exits.
4. nginx starts after the frontend init succeeds.

Open `http://YOUR_SERVER_IP/` and log in.

## 5. HTTPS (Let's Encrypt)

Prerequisites: domain A record → server IP; ports 80/443 open.

### 5.1 Obtain the certificate

Stop nginx (it owns port 80), run certbot in standalone mode, start
nginx again:

```bash
cd /opt/flowpilot
docker compose stop nginx

docker run --rm -p 80:80 certbot/certbot certonly --standalone \
  -d your-domain.example \
  --agree-tos -m you@example.com --non-interactive

docker compose start nginx
```

Certificates land in `/etc/letsencrypt/live/your-domain.example/` on
the host.

### 5.2 Production files (outside git)

Create `prod/ssl.conf` inside the repo clone (the folder is not tracked
by git, so `git pull` never conflicts with it):

`/opt/flowpilot/prod/ssl.conf`:

```nginx
server {
    listen 443 ssl;
    server_name your-domain.example;

    ssl_certificate /etc/letsencrypt/live/your-domain.example/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.example/privkey.pem;

    client_max_body_size 2m;

    location /api/webhooks/telegram {
        limit_req zone=telegram_webhook burst=5 nodelay;
        # Telegram sends its secret as X-Telegram-Bot-Api-Secret-Token;
        # the backend expects X-Telegram-Secret — map it here:
        proxy_set_header X-Telegram-Secret $http_x_telegram_bot_api_secret_token;
        proxy_pass http://backend_upstream;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /api/ {
        proxy_pass http://backend_upstream;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        root /usr/share/nginx/html;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
}

server {
    listen 80;
    server_name your-domain.example;
    return 301 https://$host$request_uri;
}
```

The `backend_upstream` and the `telegram_webhook` rate-limit zone are
defined in the repo's `nginx/nginx.conf` — the official nginx image
loads everything in `/etc/nginx/conf.d/`, so `ssl.conf` picked up by a
plain file mount reuses them.

`/opt/flowpilot/docker-compose.override.yml`:

```yaml
services:
  nginx:
    ports:
      - "443:443"
    volumes:
      - ./prod/ssl.conf:/etc/nginx/conf.d/ssl.conf:ro
      - /etc/letsencrypt:/etc/letsencrypt:ro
```

Compose merges this over `docker-compose.yml`: nginx keeps port 80 and
gains 443, certificates and `ssl.conf` are mounted. The override file
is local to the server (not in git), so updates via `git pull` do not
conflict with it.

Apply:

```bash
docker compose up -d
curl https://your-domain.example/api/health
curl -I http://your-domain.example/     # 301 → https
```

### 5.3 Certificate renewal

Certbot certificates last 90 days. Renewal stops nginx for a few
seconds (standalone mode needs port 80). Weekly cron check:

`/etc/cron.d/flowpilot-certbot`:

```
0 3 * * 1 root cd /opt/flowpilot && docker compose stop nginx && docker run --rm -p 80:80 certbot/certbot renew --quiet && docker compose start nginx
```

`renew` only actually renews when a certificate is within 30 days of
expiry, so most weekly runs are no-ops.

## 6. Telegram Webhook (real bot)

After HTTPS works, point Telegram at your server (secret token is
verified by the backend through the header mapping in `ssl.conf`):

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook" \
  -d "url=https://your-domain.example/api/webhooks/telegram" \
  -d "secret_token=<TELEGRAM_WEBHOOK_SECRET from .env>"
```

Send a message to the bot — a request should appear in the dashboard.

> The full Telegram wiring (real bot → webhook → request) was **not**
> verified end-to-end in this project yet; only the header mapping and
> the webhook endpoint were verified locally.

## 7. Updates

```bash
cd /opt/flowpilot
git pull
docker compose up --build -d
```

- New containers are created from the fresh images; the backend
  entrypoint runs `alembic upgrade head` automatically on start.
- The frontend init container re-copies the freshly built `dist/` into
  the shared volume (old hashed assets are removed first).
- Database volume and certificates are preserved.

Verify after every update:

```bash
docker compose ps
curl https://your-domain.example/api/health
docker compose logs backend --tail 50
```

Rollback (application code):

```bash
git checkout <previous-tag-or-commit>
docker compose up --build -d
```

Rolling back database migrations is manual (`alembic downgrade`) —
prefer restoring a backup taken before the update.

## 8. Backup and Restore

Daily `pg_dump` with 14-day rotation, e.g.
`/etc/cron.d/flowpilot-backup`:

```
0 4 * * * root cd /opt/flowpilot && mkdir -p backups && docker compose exec -T postgres pg_dump -U flowpilot flowpilot | gzip > backups/flowpilot-$(date +\%F).sql.gz && find backups -name "flowpilot-*.sql.gz" -mtime +14 -delete
```

Restore:

```bash
gunzip -c backups/flowpilot-2026-01-01.sql.gz | \
  docker compose exec -T postgres psql -U flowpilot flowpilot
```

Copy backups off the server regularly (scp/rsync to another machine) —
a backup that lives only on the same VPS is not a backup.

## 9. Health Monitoring

- Liveness: `curl https://your-domain.example/api/health` (plain 200,
  no auth).
- Container state: `docker compose ps` (postgres should show
  `healthy`).
- Logs: `docker compose logs -f backend` / `nginx`.
- The stack restarts automatically after a host reboot
  (`restart: unless-stopped`).

## 10. Troubleshooting

| Symptom | Check |
|---|---|
| `docker compose up` hangs at "postgres: Waiting" | `docker compose logs postgres`; wrong `POSTGRES_PASSWORD` on an existing volume (wipe: `docker compose down -v` — **destroys data**) |
| 502 from nginx | backend container down: `docker compose ps`, `docker compose logs backend` |
| Certbot "port 80 already in use" | nginx not stopped: `docker compose stop nginx` first |
| HTTPS works, HTTP does not redirect | check `server_name` in `prod/ssl.conf` matches your domain |
| Webhook returns 403 | wrong `TELEGRAM_WEBHOOK_SECRET` in `.env` or in the `setWebhook` call; after changing `.env` run `docker compose up -d` |
| 429 on login | FastAPI rate limit (20/min per IP) — wait a minute |
